# mdblog/ —— 随手写的笔记放这里

这个文件夹里所有 `.md` 都会在 `npm run deploy` 时**自动转换成博客文章**。

## 怎么用

1. 在这里新建一个 `.md` 文件(可以建子文件夹);
2. 正常写 Markdown,**不需要**写 front-matter;
3. 跑 `npm run deploy`,它就出现在博客上了。

```bash
npm run mdblog              # 只做同步,不构建不发布
npm run mdblog -- --dry-run # 只看会做什么,不落盘
npm run server              # 本地预览
npm run deploy              # 同步 + 构建 + 发布
```

## 自动处理的事

| 你写的 | 变成 |
| --- | --- |
| 正文第一个 `# 标题` | 文章标题(那一行会从正文里去掉,避免出现两个大标题) |
| 没有 `# 标题` | 用文件名当标题 |
| 文件修改时间 | 文章日期 |
| 子目录名 | 分类,比如 `mdblog/数学/xxx.md` → 分类「数学」 |
| 相对路径的图片 | 复制到 `source/images/mdblog/<slug>/` 并改写路径 |

文件名决定网址:`mdblog/数学/fibonacci-golden-ratio.md` → `posts/fibonacci-golden-ratio/`。
两个不同目录下同名的文件会自动带上目录前缀避免撞车。

## 想自己指定怎么办

在文件开头加 front-matter,写了就以你写的为准:

```markdown
---
title: 自定义标题
date: 2026-09-25 20:00:00
categories: 随笔
tags: [Hexo, 笔记]
slug: my-own-url        # 自定义网址,不写就用文件名
---

正文……
```

## 几条规则

- **单向同步。** 这里的文件是源;`source/_posts/` 里由它生成的文章带
  `mdblog_source:` 标记,是生成物,**改了会被下一次同步覆盖**。
- **手写的文章不受影响。** 直接在 `source/_posts/` 里写的文章没有那个标记,
  同步时绝不会被碰。
- **删掉即下线。** 从这里删掉一篇,对应的博客文章也会被删掉(git 里能找回)。
- **`_` 和 `.` 开头的文件/文件夹会被跳过**,用来放说明、草稿、附件。
- 笔记里同样可以用 `exec` 代码格,见 `README.md` 的「在文章里插可运行的代码块」。
